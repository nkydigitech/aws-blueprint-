Chapter 00 - The Missing Manual

What is Cloud? What is AWS? In Plain English

This is what the old page skipped. Let's use Ikorodu logic, not textbook English.

🏠

What is "Cloud" Really?

Before cloud: You buy a big generator, buy diesel, service it yourself just to power your small shop. That's owning servers.

Cloud: You connect to IKEDC. You use light when you need it, pay for what you use, someone else maintains the grid.

Cloud = renting computers, storage, and network on the internet instead of buying your own.

☁️

What is AWS then?

AWS (Amazon Web Services) is Amazon's IKEDC for computers. The biggest warehouse in the world renting you 200+ services:

  • Computers to run your code (EC2)
  • Warehouses to store files (S3)
  • Security bouncers (IAM)
  • Traffic police (Load Balancer)
  • Phonebook (Route53)

33% of the internet runs on AWS — Netflix, Jumia, banks, your favorite apps.

🚀 What is AWS FOR?

• Host websites without buying servers
• Store unlimited files (like Google Drive for apps)
• Run apps that auto-scale when 10k users rush in
• Keep data safe with auto-backups & alarms
• Send SMS alerts when your app has problem

Chapter 02

AWS Architecture

Understanding how AWS is structured is crucial before you start building.

Global Infrastructure Hierarchy

+-----------------------------------------------------------------------------+ | AWS GLOBAL INFRASTRUCTURE | +-----------------------------------------------------------------------------+ | Region = Geographic area (e.g., us-east-1, eu-west-1) | | AZ = Availability Zone (isolated data center) - Ikeja vs Yaba analogy | | Edge = CDN endpoint for CloudFront (450+ worldwide) | +-----------------------------------------------------------------------------+ | [us-east-1] [eu-west-1] [ap-south-1] [sa-east-1] | | | | | | | | [AZ-A, AZ-B, AZ-C] per Region - If one burns, others keep you online | +-----------------------------------------------------------------------------+

Key Concepts

  • Region: Geographic area with multiple AZs
  • AZ: One or more discrete data centers
  • Edge Location: CDN endpoint for CloudFront
  • Local Zone: Extension closer to users

Design Principles

  • High Availability: Deploy across 2+ AZs
  • Fault Tolerance: Automatic failover
  • Scalability: Scale up or out
  • Security: Defense in depth
💡
Pro Tip

Always design for at least 2 AZs in production. If one data center catches fire, floods, or loses power, your app stays online.

Chapter 04 = Lab 4 in Repo

IAM - Bouncers & ID Cards

IAM is foundation of AWS security. Analogy: Bouncers checking ID cards at estate gate.

👤

Users

Individual people. Each has unique credentials. Never share.

👥

Groups

Collections with shared permissions. "Developers" group gets EC2+S3.

📜

Policies

JSON docs defining permissions. Least privilege - only what's needed.

🎭

Roles

Temporary credentials for services. EC2 assumes role to access S3.
