Chapter 02

AWS Architecture

Understanding how AWS is structured is crucial before you start building. Let's explore the foundational concepts.

Global Infrastructure Hierarchy

+-----------------------------------------------------------------------------+ | AWS GLOBAL INFRASTRUCTURE | +-----------------------------------------------------------------------------+ | | | +-------------+ +-------------+ +-------------+ +-------------+ | | | Region | | Region | | Region | | Region | | | | us-east-1 | | eu-west-1 | | ap-south-1 | | sa-east-1 | | | | (N.Virginia)| | (Ireland) | | (Mumbai) | | (Sao Paulo) | | | +------+------+ +------+------+ +------+------+ +------+------+ | | | | | | | | v v v v | | +-------------+ +-------------+ +-------------+ +-------------+ | | | AZ-A | | AZ-A | | AZ-A | | AZ-A | | | | +-----+ | | +-----+ | | +-----+ | | +-----+ | | | | | DC | | | | DC | | | | DC | | | | DC | | | | | +-----+ | | +-----+ | | +-----+ | | +-----+ | | | +-------------+ +-------------+ +-------------+ +-------------+ | | +-------------+ +-------------+ +-------------+ +-------------+ | | | AZ-B | | AZ-B | | AZ-B | | AZ-B | | | | +-----+ | | +-----+ | | +-----+ | | +-----+ | | | | | DC | | | | DC | | | | DC | | | | DC | | | | | +-----+ | | +-----+ | | +-----+ | | +-----+ | | | +-------------+ +-------------+ +-------------+ +-------------+ | | +-------------+ +-------------+ +-------------+ +-------------+ | | | AZ-C | | AZ-C | | AZ-C | | AZ-C | | | | +-----+ | | +-----+ | | +-----+ | | +-----+ | | | | | DC | | | | DC | | | | DC | | | | DC | | | | | +-----+ | | +-----+ | | +-----+ | | +-----+ | | | +-------------+ +-------------+ +-------------+ +-------------+ | | | | Region = Geographic area (e.g., US East, Europe) | | AZ = Availability Zone (isolated data center within a region) | | DC = Data Center (physical building with servers) | | | +-----------------------------------------------------------------------------+

Key Concepts

  • Region: A physical location worldwide with multiple AZs
  • Availability Zone (AZ): One or more discrete data centers
  • Edge Location: CDN endpoint for CloudFront (450+ worldwide)
  • Local Zone: Extension of a region closer to users
  • Wavelength: 5G edge computing infrastructure

Design Principles

  • High Availability: Deploy across multiple AZs
  • Fault Tolerance: Automatic failover on failure
  • Scalability: Scale up or out automatically
  • Security: Defense in depth at every layer
  • Cost Optimization: Right-size resources always
💡
Pro Tip

Always design for at least 2 AZs in production. If one data center catches fire, floods, or loses power, your application stays online. AWS handles the failover automatically when configured correctly.

Navigate to the AWS homepage and click "Create an AWS Account." You'll need:

Select Personal for learning. Complete the contact information form with your real details - AWS verifies identity and may suspend accounts with false information.

Enter Payment Information

4

Chapter 04

Identity & Access Management (IAM)

IAM is the foundation of AWS security. Master it, and you've mastered half of AWS security. Ignore it, and you will have a very bad day.

IAM Core Concepts

👤

Users

Individual people or applications that need access. Each user has unique security credentials. Never share credentials between users.

👥

Groups

Collections of users with shared permissions. Example: "Developers" group gets EC2 and S3 access. Add a user to a group, they inherit all permissions.

📜

Policies

JSON documents that define permissions. Attach policies to users, groups, or roles. Follow least privilege - grant only what's needed.

🎭

Roles

Temporary credentials for AWS services or federated users. An EC2 instance assumes a role to access S3. No permanent credentials stored.

Creating Your First IAM Admin User

💡
IAM Best Practices

1. Never use Root Account for daily tasks
2. Enable MFA on Root and all Admin users
3. Use Groups to assign permissions, not individual users
4. Rotate access keys every 90 days
5. Use Roles for EC2/Lambda, not hardcoded credentials
6. Regularly audit with IAM Credential Report

Lab 1: S3 Static Website Hosting

Host a static website on S3 with CloudFront CDN

Dev 15 min

Architecture

+-------------+ +-------------+ +-------------+ | User |-------->| CloudFront |-------->| S3 | | (Browser) | HTTPS | CDN | Origin | Bucket | | |<--------| (Edge) |<--------| (Website) | +-------------+ Cache +-------------+ Fetch +-------------+

Prerequisites

  • AWS CLI configured with admin access
  • Basic HTML file for testing

Step 1: Create S3 Bucket

Bash
# Set variables
export BUCKET_NAME="my-awesome-site-$(date +%s)"
export REGION="us-east-1"

# Create bucket
aws s3api create-bucket \
    --bucket $BUCKET_NAME \
    --region $REGION

# Enable static website hosting
aws s3api put-bucket-website \
    --bucket $BUCKET_NAME \
    --website-configuration '{"IndexDocument":{"Suffix":"index.html"},"ErrorDocument":{"Key":"error.html"}}'

Step 2: Create Bucket Policy

Bash
cat > bucket-policy.json << 'EOF'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadGetObject",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::$BUCKET_NAME/*"
    }
  ]
}
EOF

# Apply policy
aws s3api put-bucket-policy \
    --bucket $BUCKET_NAME \
    --policy file://bucket-policy.json

# Remove block public access
aws s3api put-public-access-block \
    --bucket $BUCKET_NAME \
    --public-access-block-configuration "BlockPublicAcls=false,IgnorePublicAcls=false,BlockPublicPolicy=false,RestrictPublicBuckets=false"

Lab 3: Serverless API with Lambda & API Gateway

Build a REST API without managing any servers

Dev 25 min

Architecture

+-------------+ +-------------+ +-------------+ | Client |-------->| API Gateway |--------> Lambda | | (Any App) | HTTPS | (REST) | JSON | Function | | |<--------| |<--------| (Python) | +-------------+ +-------------+ +-------------+

Prerequisites

  • AWS CLI configured
  • Python 3 installed locally

Step 1: Create Lambda Function Code

Python
# lambda_function.py
import json

def lambda_handler(event, context):
    http_method = event.get('httpMethod', 'GET')
    
    if http_method == 'GET':
        return {
            'statusCode': 200,
            'headers': {
                'Content-Type': 'application/json',
                'Access-Control-Allow-Origin': '*'
            },
            'body': json.dumps({
                'message': 'Hello from AWS Lambda!',
                'service': 'AWS Blueprint Lab 3',
                'timestamp': context.aws_request_id
            })
        }
    
    elif http_method == 'POST':
        body = json.loads(event.get('body', '{}'))
        name = body.get('name', 'World')
        return {
            'statusCode': 200,
            'headers': {
                'Content-Type': 'application/json',
                'Access-Control-Allow-Origin': '*'
            },
            'body': json.dumps({
                'message': f'Hello, {name}!',
                'service': 'AWS Blueprint Lab 3',
                'method': 'POST'
            })
        }
    
    return {
        'statusCode': 400,
        'body': json.dumps({'error': 'Unsupported method'})
    }

Step 2: Create IAM Role for Lambda

Bash
# Create trust policy
cat > trust-policy.json << 'EOF'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": { "Service": "lambda.amazonaws.com" },
      "Action": "sts:AssumeRole"
    }
  ]
}
EOF

# Create role
export ROLE_ARN=$(aws iam create-role \
    --role-name aws-blueprint-lambda-role \
    --assume-role-policy-document file://trust-policy.json \
    --query 'Role.Arn' \
    --output text)

# Attach basic execution policy
aws iam attach-role-policy \
    --role-name aws-blueprint-lambda-role \
    --policy-arn arn:aws:iam::aws:policy/service-role/AWSLambdaBasicExecutionRole

echo "Role ARN: $ROLE_ARN"
✓ Expected Output
Role ARN: arn:aws:iam::123456789012:role/aws-blueprint-lambda-role

Step 3: Package and Deploy Lambda

Bash
# Create deployment package
zip function.zip lambda_function.py

# Create Lambda function
export FUNCTION_ARN=$(aws lambda create-function \
    --function-name aws-blueprint-api \
    --runtime python3.11 \
    --role $ROLE_ARN \
    --handler lambda_function.lambda_handler \
    --zip-file fileb://function.zip \
    --query 'FunctionArn' \
    --output text)

echo "Function ARN: $FUNCTION_ARN"
✓ Expected Output
Function ARN: arn:aws:lambda:us-east-1:123456789012:function:aws-blueprint-api

Step 4: Create API Gateway

Bash
# Create REST API
export API_ID=$(aws apigateway create-rest-api \
    --name 'aws-blueprint-api' \
    --query 'id' \
    --output text)

# Get root resource ID
export ROOT_ID=$(aws apigateway get-resources \
    --rest-api-id $API_ID \
    --query 'items[0].id' \
    --output text)

# Create /hello resource
export RESOURCE_ID=$(aws apigateway create-resource \
    --rest-api-id $API_ID \
    --parent-id $ROOT_ID \
    --path-part hello \
    --query 'id' \
    --output text)

# Create GET method
aws apigateway put-method \
    --rest-api-id $API_ID \
    --resource-id $RESOURCE_ID \
    --http-method GET \
    --authorization-type NONE

# Create POST method
aws apigateway put-method \
    --rest-api-id $API_ID \
    --resource-id $RESOURCE_ID \
    --http-method POST \
    --authorization-type NONE

# Integrate GET with Lambda
aws apigateway put-integration \
    --rest-api-id $API_ID \
    --resource-id $RESOURCE_ID \
    --http-method GET \
    --type AWS_PROXY \
    --integration-http-method POST \
    --uri "arn:aws:apigateway:us-east-1:lambda:path/2015-03-31/functions/$FUNCTION_ARN/invocations"

# Integrate POST with Lambda
aws apigateway put-integration \
    --rest-api-id $API_ID \
    --resource-id $RESOURCE_ID \
    --http-method POST \
    --type AWS_PROXY \
    --integration-http-method POST \
    --uri "arn:aws:apigateway:us-east-1:lambda:path/2015-03-31/functions/$FUNCTION_ARN/invocations"

# Grant API Gateway permission to invoke Lambda
aws lambda add-permission \
    --function-name aws-blueprint-api \
    --statement-id apigateway-invoke \
    --action lambda:InvokeFunction \
    --principal apigateway.amazonaws.com \
    --source-arn "arn:aws:execute-api:us-east-1:$(aws sts get-caller-identity --query Account --output text):$API_ID/*/GET/hello"

aws lambda add-permission \
    --function-name aws-blueprint-api \
    --statement-id apigateway-invoke-post \
    --action lambda:InvokeFunction \
    --principal apigateway.amazonaws.com \
    --source-arn "arn:aws:execute-api:us-east-1:$(aws sts get-caller-identity --query Account --output text):$API_ID/*/POST/hello"

# Deploy API
aws apigateway create-deployment \
    --rest-api-id $API_ID \
    --stage-name prod

export API_URL="https://$API_ID.execute-api.us-east-1.amazonaws.com/prod/hello"
echo "API URL: $API_URL"
✓ Expected Output
API URL: https://abc123def.execute-api.us-east-1.amazonaws.com/prod/hello

Prod Lab 1: Multi-AZ Web Application with Auto Scaling

Build a production-ready web app with VPC, ALB, Auto Scaling across multiple AZs

Prod 45 min

Architecture

+-------------+ | Route 53 | | (DNS) | +------+------+ | v +------------------+ +------------------+ | Internet |<------------>| ALB (Public) | | | HTTPS | (Multi-AZ) | +------------------+ +--------+---------+ | +----------------------+----------------------+ | | | v v v +----------------+ +----------------+ +----------------+ | AZ-1a | | AZ-1b | | AZ-1c | | +------------+ | | +------------+ | | +------------+ | | | EC2 (ASG) | | | | EC2 (ASG) | | | | EC2 (ASG) | | | | t3.micro | | | | t3.micro | | | | t3.micro | | | +------+-----+ | | +------+-----+ | | +------+-----+ | | | | | | | | | | | v | | v | | v | | +------------+ | | +------------+ | | +------------+ | | | RDS |<|----|>| RDS |<|----|>| RDS | | | | (Multi-AZ) | | | | (Multi-AZ) | | | | (Multi-AZ) | | | +------------+ | | +------------+ | | +------------+ | +----------------+ +----------------+ +----------------+

Prerequisites

  • AWS CLI with admin access
  • Understanding of VPC, subnets, and security groups
  • Budget awareness (uses t3.micro - within Free Tier)

Step 1: Create VPC and Subnets

Bash
export REGION="us-east-1"
export VPC_CIDR="10.0.0.0/16"

# Create VPC
export VPC_ID=$(aws ec2 create-vpc \
    --cidr-block $VPC_CIDR \
    --tag-specifications 'ResourceType=vpc,Tags=[{Key=Name,Value=aws-blueprint-vpc}]' \
    --query 'Vpc.VpcId' --output text)

echo "VPC ID: $VPC_ID"

# Create Internet Gateway
export IGW_ID=$(aws ec2 create-internet-gateway \
    --tag-specifications 'ResourceType=internet-gateway,Tags=[{Key=Name,Value=aws-blueprint-igw}]' \
    --query 'InternetGateway.InternetGatewayId' --output text)

aws ec2 attach-internet-gateway --internet-gateway-id $IGW_ID --vpc-id $VPC_ID

# Create public subnets in 3 AZs
export SUBNET1=$(aws ec2 create-subnet \
    --vpc-id $VPC_ID --cidr-block "10.0.1.0/24" --availability-zone "${REGION}a" \
    --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=public-1a}]' \
    --query 'Subnet.SubnetId' --output text)

export SUBNET2=$(aws ec2 create-subnet \
    --vpc-id $VPC_ID --cidr-block "10.0.2.0/24" --availability-zone "${REGION}b" \
    --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=public-1b}]' \
    --query 'Subnet.SubnetId' --output text)

export SUBNET3=$(aws ec2 create-subnet \
    --vpc-id $VPC_ID --cidr-block "10.0.3.0/24" --availability-zone "${REGION}c" \
    --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=public-1c}]' \
    --query 'Subnet.SubnetId' --output text)

# Create route table and associate
export RT_ID=$(aws ec2 create-route-table --vpc-id $VPC_ID \
    --tag-specifications 'ResourceType=route-table,Tags=[{Key=Name,Value=public-rt}]' \
    --query 'RouteTable.RouteTableId' --output text)

aws ec2 create-route --route-table-id $RT_ID --destination-cidr-block 0.0.0.0/0 --gateway-id $IGW_ID

for subnet in $SUBNET1 $SUBNET2 $SUBNET3; do
    aws ec2 associate-route-table --route-table-id $RT_ID --subnet-id $subnet
    aws ec2 modify-subnet-attribute --subnet-id $subnet --map-public-ip-on-launch
done

echo "VPC Setup Complete!"
echo "Subnets: $SUBNET1, $SUBNET2, $SUBNET3"

# Create Target Group
export TG_ARN=$(aws elbv2 create-target-group \
    --name aws-blueprint-tg --protocol HTTP --port 80 --vpc-id $VPC_ID \
    --health-check-path /index.php --target-type instance \
    --query 'TargetGroups[0].TargetGroupArn' --output text)

# Create Auto Scaling Group
aws autoscaling create-auto-scaling-group \
    --auto-scaling-group-name aws-blueprint-asg \
    --launch-template LaunchTemplateName=aws-blueprint-launch-template,Version='$Latest' \
    --min-size 2 --max-size 6 --desired-capacity 3 \
    --target-group-arns $TG_ARN \
    --vpc-zone-identifier "$SUBNET1,$SUBNET2,$SUBNET3" \
    --health-check-type ELB --health-check-grace-period 300 \
    --tags Key=Name,Value=aws-blueprint-asg-instance,PropagateAtLaunch=true

# Create scaling policy
aws autoscaling put-scaling-policy \
    --auto-scaling-group-name aws-blueprint-asg \
    --policy-name cpu-scale-up --policy-type TargetTrackingScaling \
    --target-tracking-configuration 'PredefinedMetricSpecification={PredefinedMetricType=ASGAverageCPUUtilization},TargetValue=60.0'

echo "Auto Scaling Group Created!"
